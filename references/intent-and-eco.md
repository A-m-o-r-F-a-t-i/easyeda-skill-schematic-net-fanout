# 原理图需求补全、用户介入与增量同步

本文件定义电子设计任务的协作契约。用户给出的例子用于推导同类需求，初次列举的修改项作为任务起点。以最新有效设计持续交付可继续布板、可接线和可维护的结果，用户无需在每一步重复完整要求。

## 1. 主动把目标补成完整设计意图

先利用已知上下文回答：电路供什么设备使用，输入输出是什么，用户怎样接线、调试和维护，哪些约束已经确定。主动补查去耦、默认态、保护链、跨页网络、接口命名、调试保留脚、库引脚映射、相关PCB变化与标识。发现问题后给出具体实施选择，不能把整个设计问题交回用户填长问卷。

意图优先级为：用户最新明确指令及排除项 → 当前目标工程的有效人工修改 → 仍适用的已确认项目约束 → 从同类已批准电路和原厂条件推导的建议。用户刚改变的目标更新旧计划。器件实际参数和连接状态必须读取验证，不能从这种优先级推导出不存在的技术事实。

| 信息类别 | 默认行为 | 如何说明 |
| --- | --- | --- |
| 已有事实 | 从最新工程、先前已给参数或资料读取，直接沿用 | 不重复问已回答的问题 |
| 可逆、低影响的合理补全 | 主动决定并实施，如局部对齐、已有功能命名、补针序表、清理多余标签 | 对会影响理解的推定简述采用什么、依据什么 |
| 已定功能下的必要配套 | 按手册和现有规则补外围、保护通道或连接，计入BOM/ECO | 说明由此新增或改变的电路，核对成本与兼容性 |
| 必须由用户定方向 | 提供倾向方案、备选和实际影响，集中询问关键分歧 | 未决定前仅推进不依赖该决定的部分 |
| 尚未取得的电气事实 | 优先查询资料或读工程；仍未知则标出受影响项 | 不以猜测电流、耐压、最大输入或引脚电平批准电路 |

**值得说明的推定**：新增的默认配置、接口功能归属、供电方向、零件替代方案、影响接线的命名、范围扩充。常规对齐和小范围文字避让无需逐项播报。推定说明写在简短设计说明/结果中，不印成板上或原理图中的长段小字。

**必须定方向的例子**：主从连接方式、需不需要隔离、输入电压范围和持续负载在资料中无法确定、改变既有线缆针序、增加主要功能、突破确定的板框/层数/预算。纯字号和标签排布一般可直接决定。用户只说“24V供电”时，不能把24V当作已核验的最高瞬态；接口带5V供电也不能推出通信脚为5V逻辑。

提问聚焦于一个实际决策，说明推荐方向及另一个方向的代价。询问前先读工程和既有上下文。缺少某个方向性决定不妨碍整理已有图、核对器件、设计接口说明和准备不依赖该决定的部分。

## 2. 从少量例子推广到同类事项

“把这个接口做成排阻＋ESD”应同时检查同范围同类外接信号是否遗漏及保护前后分网，但不把CAN、模拟、I²C和电源针机械套成同一元件值。“整理原理图”默认包含局部连接可读、分区、属性、孤线、网表和接口说明，不能只换颜色。

“修正同型连接器”先比较真实脚号、功能与外部线缆兼容性。同型外壳不保证同针序，展示并处理真正差异。未经既有要求支持，不为外观统一交换TX/RX或电源脚。若用户明确要求统一针序，则该选择已定，无需重复询问，直接落实并同步相关图纸、PCB和标识。

“换一个更合适的电源芯片”默认把反馈、补偿、电感、电容、使能、热、倒灌和布局影响一起考虑。合理补全服务于现有目标，不擅自增加无线、隔离、接口、付费工艺、公共库修改或下单。

## 3. 接受任何阶段的用户介入

用户可在选型、绘制、布局、布线、ECO、丝印或验收期间插入文字指令，也可在编辑器中增删改器件、连接、属性或位置。工程计划是可以更新的工作依据，不把用户改动自动视作错误并恢复旧状态，不要求用户全程停止编辑。

在下一次写入前、ECO预览前、切页/切板后、收到新指令后以及阶段验收前，读取相关真实状态。读回发现变化时，撤销尚未执行的过期计划部分，保留已完成且仍成立的工作，更新受影响器件、网络与测试项。一次调用可能已经部分执行，先读回后续作，不能承诺在调用中途瞬时抢占或以全局撤销恢复。

按字段和对象合并：用户移动器件时保留新位置，后续改值不带回旧坐标；用户删掉某支路时不再执行旧的创建任务；用户手改文字时保留其含义与版式意图，核对它是否仍对应最新网络。用户已在做一小块未闭合电路时，暂避该区域并继续独立区域，稳定读取后重新评估。持续冲突、半成品或互斥意图才需询问最小分歧。

## 4. 原理图同步PCB的默认范围

**默认模式：同一目标板的全部有效差异，增量应用。** 用户要求修改原理图并更新PCB时，在转换时重新读取该板全部相关原理图页与PCB。初次只提到1、2项，后来发现其他已经形成的有效修改，默认纳入本次ECO并处理相关布局、铜和丝印，不因未逐项口述而停下来索取授权。

“只提到了1、2项”不构成排他限制。用户明确说“只同步1、2，其他暂不改”或标记了实验分区，则保留该排除。该默认模式不跨工程、板、装配变体或明确不转PCB的器件。尚未启用的备选电路按实际工程属性保留排除，不能把DNP和不转PCB简单等同。

无冲突的属性调整、网络修改、有效新增/删除器件、已选定的封装替换和接口变更均可进入ECO。删除要用稳定器件关联及当前源端缺失确认，不能把仅PCB存在的安装孔、定位标记、净桥、测试结构或用户临时布局试验误删。缺少稳定关联、源端半完成、存在电气错误、双边修改同一电气属性或需要新增方向决策时，只暂缓相关依赖组。

预览与核查是执行步骤，不是每次自动弹出的用户确认门。说明新增合并的差异类别和需要重布的范围，无冲突时直接应用。全部读取之后只写差异，不清空PCB再导入，不用旧原理图或旧截图覆盖用户现场。

## 5. 从最新双边状态生成ECO

1. 确定工程、板、原理图、目标PCB和装配变体。读取编辑器当前有效内容；存盘前避免覆盖尚未提交的属性输入，不能通过重载网页丢弃用户未保存编辑。
2. 用稳定器件关联ID及符号引脚到封装焊盘关系配对，位号作为可变属性。原理图页坐标与PCB坐标分别管理，原理图移动不触发全板布局传递。
3. 汇总全部差异并建立依赖组。比较上次已知状态、当前原理图和当前PCB：源端电气变化传播到PCB，PCB位置/旋转/面/已有合法铜/文字布局保留，双边同字段不一致才是需解释的冲突。没有旧快照也可读取当前差异，不因缺少历史日志拒绝无冲突同步。
4. 对正常差异直接形成增量应用。涉及真实器件删除或封装替换时保存双方原生可恢复副本，普通同名网络/文档备份不要求逐批生成。某些原生ECO不能撤销，不能以Ctrl+Z作为唯一恢复方案。[S1]
5. 先判断“同连接仅改名”与“连接拓扑改变”。仅改名可核查后更新对应铜网络。增删器件、分裂/合并网络或换脚后，读取关联旧铜并重规划，不能把整个旧铜组盲目赋成新网络来隐藏短接。官方文档说明导入变更可能保留旧走线，且更新导线网络需要复核。[S1]
6. ECO后重读器件、焊盘、网络和相关铜，检查用户位置与文字未被意外覆盖。新增器件继续布局布线，已变网络修复后重铺、运行原生检查，更新接口表、针序丝印及失效的验证记录。
7. 当前公开`importChanges`以及PCB MCP导入工具只支持整板应用，没有逐项排除参数或类型化源端预览。存在排除项/冲突时，只有验证过的选择性路径才能分离差异；没有这种能力时暂缓该板整体导入，继续不依赖ECO的工作并解决最小分歧。不能用一个PCB摘要代替源端审查，也不能声称仅跳过冲突组却调用整板导入。源端继续变化时重新比较。

PCB侧仅位号或器件属性改动可按原生支持的反向更新流程协调；当前官方文档限制反向同步的元件增删与网络变更，不能声称所有PCB编辑都能一键反推。[S2]

## 6. 把接口可用性传递到PCB

建立工程内轻量接口映射：接口位号/稳定ID、功能名、所属主控或通道、焊盘号、实际网名、显示短名、板端信号方向、供电电压及输入/输出角色。只保留影响接线的数据，不强制生成冗余日志。该映射供PCB丝印与最终交付复核。

功能名和短名来自真实电路，`UART1_TX_EXT`可在已核验UART1组内显示TX，但网络本身不因此改名。两个主控同号UART需保留主从/通道区分。电源角色或逻辑域未知时不印推定额定值，以必要问题解决。新网表使旧接口文字失效时，更新关联丝印也是同步任务的一部分。

默认同时补足已有按键、跳帽、LED、电源端、调试接口和测试点的名称/状态说明，处理极性、1脚和易插错关系。用户友好不等于更多装饰，对当前功能无帮助的长说明、无用接口与未定功能不自动加到板上。

## 7. 完成与告知

完成原理图＋PCB联动任务时，用最终源端网表与PCB逐脚对照，说明实际并入的额外修改、仍需定向或待验证的少量事项。布局、铜、重铺和接口丝印须对应同一最终版本。用户的介入改变部分结果时只重新检查受影响项，不丢弃无关已完成成果。

用户明确只要求原理图、评审或指定局部步骤时，按该范围完成，不能擅自写PCB。本Skill维护任务也不自动操作正在打开的工程。

## 导入试验的验证等级

关联正确、摘要一致、无差异importChanges返回成功，只验证无差异导入路径。器件增删、换封装、交换针位以及同板额外修改的传播，需要有真实差异的独立用例，不能由无变化导入自动宣布通过。隔离试验前用原生工程备份保存源端及目标，恢复后检查规则和派生覆铜。默认合并有效差异的协作规则保持不变，实际写入范围服从工具能够选择的范围。
